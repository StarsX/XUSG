# Vulkan path status

Scope is XUSG core and Ultimate. Ray tracing and EZ are out of scope. The default API is `API::DIRECTX_12`. Release x64 `XUSG.dll` has been built. RenderingX Release x64 has been run on DirectX 12 and Vulkan. Win32 has not been built.

`assert` is compiled out in Release (`NDEBUG`). Interfaces marked unimplemented or abandoned below fail silently or return empty in Release.

## API selection

`Device::SetApi` is the only function that takes an API. No class stores one. The value lives in the XUSG DLL. The default is `API::DIRECTX_12`.

The first `Device::GetApi()` locks the API. `MakeUnique`, `MakeShared`, and `LoadSDKMesh` also lock, because some of them never call `GetApi`. After the lock, `SetApi` asserts and returns without changing the value. That early return still runs in Release.

RenderingX does not store the API. `-vk` / `-vulkan` calls `Device::SetApi(API::VULKAN)` while parsing the command line, before `OnInit` and before any factory. A failed Vulkan device create does not switch back to DirectX 12.

## Device extensions

The device is created as Vulkan 1.3 when the loader and physical device allow it. Otherwise creation drops to 1.2, 1.1, or 1.0. A core extension with no fallback must be available, or `createDevice` fails. A feature that is already in the selected device API version does not need its extension name. If the device is older than the version that promoted the feature, the extension name is enabled instead. If the instance is also older than that version and the extension is missing, creation fails. A 1.0 instance also requires `VK_KHR_get_physical_device_properties2`. Extensions that have a fallback in core, and Ultimate extensions, only disable the matching feature. The device is still created.

`VK_KHR_synchronization2`, `VK_KHR_maintenance5`, `VK_KHR_robustness_2` (otherwise `VK_EXT_robustness_2`), `VK_EXT_device_generated_commands`, `VK_KHR_shader_untyped_pointers`, vertex attribute divisor (`VK_KHR_vertex_attribute_divisor`, otherwise `VK_EXT_vertex_attribute_divisor`), `VK_EXT_transform_feedback`, `VK_EXT_conservative_rasterization`, and `VK_EXT_conditional_rendering` are enabled when present. A false feature bit disables that feature. A missing extension does not fail device creation. synchronization2 is in Vulkan 1.3, so 1.3 uses the core feature. Without it, a resource barrier is split into `vkCmdPipelineBarrier` calls by `srcStage` / `dstStage`, and queue submit uses `vkQueueSubmit`. `VK_KHR_depth_stencil_resolve` is in Vulkan 1.2 and has no separate feature bit. The extension name is written only when the device is below 1.2 and the extension is present. MIN/MAX availability comes from `supportedDepthResolveModes` and `supportedStencilResolveModes`. A missing mode does not fail device creation. `VK_KHR_buffer_device_address`, `VK_KHR_timeline_semaphore`, and `VK_KHR_shader_float16_int8` are in Vulkan 1.2. Below 1.2 their extension names are enabled. Below a 1.2 instance those three must be present, and their own feature structs are used instead of `VkPhysicalDeviceVulkan12Features`. maintenance5 is in Vulkan 1.4, so a device created at 1.3 still uses the extension name. The divisor feature is in Vulkan 1.4, so a device created at 1.3 still uses the extension name. `VK_EXT_custom_border_color` is enabled only when both `customBorderColors` and `customBorderColorWithoutFormat` are true. Otherwise samplers use a standard border. Mesh shader and fragment shading rate enable only the feature bits the device reports.

Shader model 6.0–6.8 and wave features are enabled when available. A false bit, or a missing required extension, turns that item off. The device is still created. Callers assert and return when the flag is false. `shaderInt64` is a Vulkan 1.0 feature. The four 16-bit storage bits and `shaderDrawParameters` are in Vulkan 1.1. Below 1.1 the names `VK_KHR_16bit_storage` and `VK_KHR_shader_draw_parameters` are enabled. Below 1.1, `VK_EXT_shader_subgroup_ballot` and `VK_EXT_shader_subgroup_vote` may also be enabled. ## Descriptor sets and shader reflection

DirectX 12 keeps every view type in space 0. Vulkan sets are `XUSG_VK_SPACE_CBV` 0, `XUSG_VK_SPACE_SRV` 1, `XUSG_VK_SPACE_UAV` 2, and `XUSG_VK_SPACE_SAMPLER` 3. `GetCBVSpace`, `GetSRVSpace`, `GetUAVSpace`, and `GetSamplerSpace` return those values. `XUSG_VK_BINDING(b, s)` emits `[[vk::binding(b, s)]]` when `XUSG_SPIRV` is defined. FXC shader model 5.0 does not accept `vk::` attributes, so the macro is empty otherwise.

`ShaderLib::CreateShader(stage, index, pDxbc, dxbcSize, pSpirv, spirvSize)` selects the blob from `Device::GetApi()`. Vulkan uses the SPIR-V bytes. DirectX 12 uses the DXBC bytes. Both live in one binary.

The SPIR-V reflector reads `OpName`, `DecorationBinding`, and `DecorationDescriptorSet`. A missing set decoration is 0. `GetResourceBindingPointByName` returns `UINT32_MAX` when the name is missing. It has no default argument. `GetResourceSpaceByName` still takes `defaultVal`, which defaults to `UINT32_MAX`. DXIL reflection returns `desc.Space`. DXBC reflection returns 0. `Reflector::ReflectBinding` keeps the estimated slot when the name is missing. When the name is present, it asserts that the reflected space equals the expected `Get*Space` value and returns the reflected slot. The estimated slot is replaced. The space is not.

## Serialized root signatures

`CreateRootSignature`, `GetRootSignature`, `CreateRootSignatureFromLibSubobject`, and `GetRootSignatureFromLibSubobject` deserialize a DX12 root signature into descriptor mappings. Lookup keys match the DX12 library.

An unnamed create prefers the `RTS0` part. If that part is absent, it accepts one RDAT `GlobalRootSignature`. Two unnamed global root signatures fail. A named lib-subobject lookup searches RDAT only, for `GlobalRootSignature` or `LocalRootSignature`, and takes the first name match. Payload versions 1.0, 1.1, and 1.2 are accepted.

Root constants become push data. Root CBV, SRV, and UAV become an 8-byte push address. A descriptor table becomes a heap slot plus a push index. Static samplers become embedded samplers. Address and comparison values in the blob are 1-based D3D12 enums. XUSG enums are 0-based, so those fields subtract 1. Static border 0 is transparent black, 1 is opaque black, and 2 is opaque white. `nodeMask` is ignored. The name is used only to find an RDAT subobject. A local root signature is decoded with the same mapping as a global one. There is no separate ray-tracing local-root bind path. The push-data size is asserted against `maxPushDataSize`.

## Abandoned, no plan to implement

These will not be implemented.

| Interface | Reason |
| --- | --- |
| Sampler feedback | `Create`, `CreateUAV`, and descriptor write return false or nullptr. `Resolve` returns immediately for `ENCODE_SAMPLER_FEEDBACK` and `DECODE_SAMPLER_FEEDBACK`. Vulkan has no hardware sampler feedback. `R32G32_UINT` plus compute is not used as a stand-in. The feature is not useful enough later |
| Work graph | `SetStateObject`, `SetProgram`, and `DispatchGraph` assert and then do nothing. `GetProgramIdentifier` asserts and returns empty. On `API::VULKAN` the `WorkGraph` factories assert and still return the DX12 type. DirectX 12 stopped maintaining work graphs at shader model 6.10 |
| Video | Command list, allocator, and queue assert when the type is `VIDEO_*`. Not planned |

| Castable format | A non-zero `numCastableFormats` creates the image with `VK_IMAGE_CREATE_MUTABLE_FORMAT_BIT` and `VkImageFormatListCreateInfo` |
| `InstanceDataStepRate` | A value other than 1 writes `VkPipelineVertexInputDivisorStateCreateInfo` only when the device has vertex attribute divisor. Without that feature the call asserts, the pipeline has no divisor state, and the instance rate stays 1. A step rate of 0 asserts |
| `patchControlPoints` | Read from the hull-shader SPIR-V Input array length, which is the input control-point count. `OutputVertices` is the output count and is not used. If the scan fails, the call asserts and then creates with 1. dxil-spirv writes the hull input array as 32, so that SPIR-V reads as 32. Every `CONTROL_POINTN` from `IASetPrimitiveTopology` is `PATCH_LIST` and does not change the count already fixed in the pipeline |
| Queue | `DIRECT`, `COMPUTE`, and `COPY` pick families the vkd3d-proton way. Compute prefers a family without graphics. Copy prefers pure transfer, then falls back. Each family has at most 4 `VkQueue`s. Further XUSG queues reuse the least loaded one. When `XUSG_SINGLE_QUEUE` is non-zero, or `VKD3D_CONFIG` contains `single_queue`, all three use queue 0 of the graphics family. Priority and `CommandQueueFlag` are still ignored. Video types assert. With more than one family, buffers and images use `VK_SHARING_MODE_CONCURRENT` |
| Swap chain | `GetCurrentBackBufferIndex` and `Present` call `vkAcquireNextImageKHR`. The acquire semaphore is waited by the next submit on the queue passed to swap-chain creation. One `VkQueue` has one wait slot, so two swap chains overwrite each other. `Present` submits an empty batch that signals the per-image render-finished semaphore, then `vkQueuePresentKHR` waits on it. `syncInterval` does not change the present mode. The mode is chosen at creation: `IMMEDIATE` for `ALLOW_TEARING`, otherwise `FIFO`. After present, the tracked state does not become `PRESENT_SRC_KHR`. A command list that draws to the back buffer must be submitted to the queue passed to `SwapChain::Create` |

## Explicitly deferred

Full Linux support is later. DirectXMath is an MIT header library. GCC 10+ and Clang 12+ can compile it on Linux. Non-Windows builds need their own `sal.h`. It is not being split out of `stdafx.h` in this pass.

| Item | Reason |
| --- | --- |
| Swap-chain surface | `SwapChain_VK::Create` treats `hWnd` as an `HWND` and calls `vkCreateWin32SurfaceKHR` and `GetModuleHandle` |
| Instance extensions | `createInstance` always enables `VK_KHR_win32_surface`. `XUSG_VK.h` defines `VK_USE_PLATFORM_WIN32_KHR` before including `vulkan.h` |
| `stdafx.h` | Pulled in by the vcxproj `ForcedIncludeFiles`, not by a source include. It contains `windows.h`, d3d12, dxgi, D3DCompiler, DirectXMath, winrt, and `__declspec(dllexport)` |

## Legacy behavior

These compile. Runtime behavior does not fully match DX12. The following are implemented as agreed and are no longer listed here: graphics and compute share push data, `DiscardResource`, multiple queues, `vkAcquireNextImageKHR`, `patchControlPoints`, an empty `VkPipelineLayout`, mapping filtered by shader stage, EXT/KHR features enabled at device creation, and `IASetVertexBuffers` with `pViews == nullptr` unbinding. The push-data convention is written above `SetComputePipelineLayout` in `XUSG.h`. When `pViews == nullptr`, DX12 passes the null pointer to `IASetVertexBuffers`. Vulkan binds `VK_NULL_HANDLE` on each slot.

- A bundle does not inherit dynamic rendering. Rendering is ended before a bundle executes.
- The command-list limit for viewports and scissors is 16, matching DX12. Both are dynamic state in the graphics pipeline. `viewportCount` and `scissorCount` are still 1, so extra viewports are not used by that pipeline.
- View instancing is stored in the PSO key and does not become multiview. Vulkan `SetNumViewInstances` stores `ViewInstanceFlags`.
- The shading-rate image is attached to the next `beginRendering`. The `SUM` combiner maps to Vulkan `MUL`.
- A normal pipeline entry point is `"main"`. A generic pipeline uses the shader name in UTF-8.
- A UAV counter lives on the object and is not written into the descriptor automatically.
- `samplerFilterMinmax` is not enabled. Min/max reduction can fail at sampler creation.
- Line rasterization is not written into the pipeline.
- A split barrier is emitted only for `END_ONLY` or `NONE`.
- Without `vkCmdBindVertexBuffers2`, the call falls back to `vkCmdBindVertexBuffers`. The vertex-buffer view size and stride are ignored. Stride comes from the input layout stored in the pipeline.
- A format with no `VkFormat` asserts and returns `VK_FORMAT_UNDEFINED`. `GetVKFilter` is an approximate map.
- `ReadFromSubresource` / `WriteToSubresource` `memcpy` only when the memory is host-visible, and they ignore the box.
- A 3D UAV ignores `wSize` / `firstWSlice`. Texture3D `GetAllocationInfo` may ignore depth.
- Different resource-view types cannot share one Vulkan set. Advanced keeps them in the sets from `Get*Space`. Callers must do the same.
- An indirect index buffer uses `VK_INDIRECT_COMMANDS_INPUT_MODE_DXGI_INDEX_BUFFER_EXT`. That is an extension enum. The binary layout of the argument follows a DXGI index buffer.
